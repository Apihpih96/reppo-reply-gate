# Reply Gate — Reppo-track demo

A small, local-only support-reply review demo built around three fictional cases. It illustrates a possible flow: inspect case evidence, review a draft, then route it to a human as allow, revise, or hold. The outcomes are fixed mock examples; they are not returned by Reppo, generated by SERV Reasoning, or based on real customer records.

## Run locally

Requirements: Python 3 and Node.js 18+ (Node is only needed for the tests). There are no package dependencies, API keys, or accounts required.

1. Unzip this package and open a terminal in the folder.
2. Start a local static server:
   ```sh
   python3 -m http.server 4173
   ```
3. Open `http://localhost:4173` in your browser.
4. Select each fictional case and choose **Run local mock review**. The panel shows a preset outcome and critique. The refund case includes a safer sample wording; the deletion case is held for a human because ownership is unverified.
5. Stop the server with Ctrl+C.

## Tests

```sh
npm test
```

The tests use Node's built-in test runner and cover the three fixed mock outcomes and their safety notes. No dependency install is needed.

## What the demo does

- Shows fictional case messages, evidence, and a policy rule.
- Shows one sample draft per case.
- Runs a deterministic, local-only preset that returns `allow`, `revise`, or `hold` for the selected sample.
- Makes the mock boundary visible in the interface and in the result panel.
- Sends no reply and never claims a customer action occurred.

## Architecture and data handling

This is a static HTML/CSS/JavaScript prototype. `app.js` contains the synthetic cases and fixed mock outcomes; the page reads those values in the browser. There is no server-side application logic, database, account system, external font, analytics, telemetry, or third-party API call. The optional Python command serves the files on the local machine only. The demo does not persist edits or case data. Do not add real customer information or credentials to the sample files.

## Integration status and privacy

This package does **not** call SERV Reasoning or Reppo. The sample drafts are hand-authored static text, not model output. The `allow / revise / hold` labels are local routing choices, not Reppo Evaluation API responses; Reppo's documented response labels are `accept / revise / reject`. Any future live integration is unimplemented and must be separately tested and disclosed. Reppo evaluation submissions may be visible to peer assessors and signed-in network users, so use synthetic test data only if a live evaluation is later added.

No API key is required or included. Never commit credentials. This package has not been published to a public repository or submitted to the hackathon.

## Demo walkthrough (about 60 seconds)

1. **Delivery status — allow:** The fictional tracking record says “label created” with no pickup scan. Show the cautious draft; the preset mock allows the evidence-grounded wording and avoids promising tomorrow.
2. **Refund request — revise:** The draft claims approval and a two-day arrival despite pending status. Show the critique and the safer sample wording.
3. **Account deletion — hold:** Identity verification is incomplete. Show that a consequential request is held for a person and no deletion is claimed.
4. **Close with the boundary:** State that these are fictional cases and preset local outcomes; there are no live model calls, Reppo evaluations, or outgoing messages.

## Track fit

Proposed for the OpenServ Hackathon 2 Reppo track. The concept is a prototype for a future SERV Reasoning draft followed by a Reppo evaluation and human review. This package demonstrates only the local interaction and safety-routing story; it does not demonstrate that integration.
